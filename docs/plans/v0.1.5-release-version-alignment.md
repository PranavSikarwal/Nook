# v0.1.5 release version alignment: implementation plan

**Goal:** Align the application version metadata at `0.1.5` and write the release notes, in one pull request, before the pull request merges and before any tag exists. Record the rule that a release bumps the version before merge.

**Architecture:** No code change. Version files, the changelog, and two documents.

**Spec:** `docs/archive/plans/v0.1.4-release-version-alignment.md` is the precedent (pull request 30). `main` is at `8f378a5` and holds the tool platform and the allowed folders view since `v0.1.4`.

## Global constraints

- Work on the branch `chore/release-v0.1.5` (already checked out, from `origin/main`). Commit locally. Do not push.
- Do the tasks in order. One task is one commit. Tick the boxes of a task in this file in the same commit.
- Change only the files a task lists. `daemon/Cargo.toml` and `worker/pyproject.toml` keep version `0.1.0`: earlier releases did not bump them. Do not edit `docs/plans/open-items-fixes.md` or `docs/plans/tool-platform-open-gaps.md`: their `v0.1.4` text names the version that was installed when they were written.
- Do not run a release, create a tag, or edit a workflow.
- Commit messages use `<type>(<scope>): <subject>` and contain no co-author or generator line.
- Prefix shell commands with `rtk`.
- Do not start any command in the background. Run each check in the foreground with a time limit, for example `timeout 280 rtk cargo metadata ...`. The harness crashes when you start a background task. The disk is nearly full: do not run `cargo clean` or a full build.
- Time box: 25 minutes.
